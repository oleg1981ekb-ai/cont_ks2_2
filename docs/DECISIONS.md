# Журнал решений (Decision Log)

Фиксирует **что** и **почему** выбрано. Новые записи добавляются сверху или
в конец с датой. Задним числом решения не переписываются: если решение
изменилось, добавляется новая запись со ссылкой на предыдущую.

Формат: дата, решение, причина, последствия/ограничения.

---

## 2026-10-31 — Handoff и журнал решений

**Решение.** Ввести `docs/HANDOFF.md` (снимок состояния, перезаписывается)
и `docs/DECISIONS.md` (append-only журнал решений).

**Причина.** Контекст между сессиями теряется; `AGENTS.md` должен содержать
стабильные правила, а не дневник. Handoff отвечает «где мы сейчас», decisions —
«почему так сделано».

**Последствия.** В конце сессии обновлять `HANDOFF.md`, `TODO.md`,
`changes.json`; решения — только когда действительно есть выбор/компромисс.

## 2026-10-31 — `docs/GIT_WORKFLOW.md` как источник истины

**Решение.** Полный git-процесс — в `docs/GIT_WORKFLOW.md`; `AGENTS.md`
содержит краткую выжимку и ссылку.

**Причина.** Дублирование правил в двух файлах приводит к расхождениям.
Один источник истины + короткая памятка для агента.

**Последствия.** При изменении процесса сначала правится GIT_WORKFLOW.md,
затем при необходимости — выжимка в AGENTS.md.

## 2026-10-31 — `compileall` вместо проверки одного файла

**Решение.** Стандартная проверка синтаксиса — рекурсивный `compileall`
по всем модулям, с исключением `venv`, `.git`, `__pycache__`.

**Причина.** Python компилирует модуль только при импорте; ошибка в
неиспользуемом модуле (`wizard_edits_new.py`, `upload_to_drive.py`,
`pdf_from_text.py`) иначе всплывёт поздно. Проверка не исполняет код и не
трогает данные.

**Последствия.** Не заменяет `ImportError`/типы/логику — только синтаксис.
Может создавать `__pycache__` (в `.gitignore`).

## 2026-10-30 — Отдельный файл архивных документов

**Решение.** Документы-«братья» месяцев, перенесённые в архив, выгружаются
в `Документы_Подобъектов.xlsx`; в БД хранятся в `documents_archived`
на уровне Подобъекта. Реализация: `builder.build_archived_docs_file`,
вызов из `main.py`, меню в `manage_sub_docs`.

**Причина.** Основной трекер не должен разрастаться служебными документами;
архив нужен отдельно, но с сохранением истории.

**Последствия.** Два выходных файла; при отсутствии архива второй файл может
не создаваться/быть пустым. Проверять оба результата.

## 2026-10-29 — Редактирование и удаление платежей

**Решение.** В `manage_payments` добавлены изменение платежа по номеру и
удаление по номеру; «Очистить все» сдвинуто на пункт 4.

**Причина.** Список `payments` — рабочие данные, нужна точечная правка без
пересоздания Подобъекта.

**Последствия.** Формула в колонке E пересобирается из актуального списка.

## 2026-10-27 — Пакет `wizard_common/crud/`

**Решение.** Разбить монолитный `wizard_common.py` на `month.py`, `status.py`,
`structure.py`, `sub_objects.py`; реэкспорт через `wizard_common/__init__.py`.

**Причина.** Файл 811 строк — сложно навигировать и тестировать; разделение
по доменам снижает связность.

**Последствия.** Импорты `import wizard_common` сохранены для совместимости;
новые функции добавлять в профильный модуль.

## 2026-10-25 — Динамические дополнительные документы

**Решение.** Для необязательных типов документов хранить `extra_docs` на
уровне месяца; в Excel выводить только добавленные пользователем.

**Причина.** Не у всех месяцев есть полный комплект документов; жёсткий
набор колонок создавал пустые строки.

**Последствия.** Стандартные документы выводятся всегда; дополнительные —
по наличию в `extra_docs`. Маски доступности — `DOCUMENT_ROLES` в `config.py`.
